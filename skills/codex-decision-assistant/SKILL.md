# 决策与三组协作

只在用户显式调用 `$codex-decision-assistant` 或明确要求使用本 Skill 时启动。先恢复当前请求的目标、范围和停止条件；后续同一任务沿用有效授权。调用不自动批准计算、部署、资金、fork／flush 或预算扩张，不改变模型与权限。

先按非空 `CODEX_GOVERNANCE_CONFIG`，否则 `${XDG_CONFIG_HOME:-$HOME/.config}/codex-governance/local.toml`，只读定位 `paths.source_root`。完整读取其 `governance/engineering-principles.md` 和 `governance/group-collaboration.md`。缺失就报告真实缺口；共同授权、身份、直接签发、PR 创建、固定回传和恢复均以协作正文为准。

从本 Skill 的真实路径上两级定位完整决策源，读取[决策程序](../../decision/decision-workflow.md)。按当前提示、目标仓库规则、相关 Issues、已指定 Projects 和项目已有裁决入口恢复业务目标、成功标准、阶段计划、授权、预算、失败历史和当前瓶颈。不同项目各自加载合同与方法，不固定领域或公共 Issue 编号。

必须从用户确认的最终业务结果、成功标准和硬约束选择路线贡献与具体工作。回读后业务目标或必要取舍仍不清晰时，要求用户补充，说明缺口、受影响工作和具体选项；依赖答案的签发、实现、实验和资源消费停在安全点。目标明确而技术方法未知时，可在既有授权内验证。第一性原则不授权改变合同；可靠负面研究结果也可推进业务判断。

平台操作通过治理源的 `scripts/group_github.py --group decision`，读取独立决策身份，不复用开发或研究账号。决策绑定使用非空 `CODEX_DECISION_ASSISTANT_CONFIG`，否则 `${XDG_CONFIG_HOME:-$HOME/.config}/codex-decision-assistant/local.toml`。绑定缺失或登录不符时停止相关平台操作，不切换全局身份。

任务签发、定时监督及困难／结果反馈都执行“项目业务目标与硬约束 → 路线贡献 → 阶段成果 → 当前瓶颈 → 执行工作 → 可核验结果”的判断。每次纠偏说明事实、取舍、具体动作和效果检查。正常长作业、合法等待、有效负面研究结果不按无效重复处理；同一失败跨 Issue、角色和会话继续累计。

恢复自己负责的路线、逻辑参与者、现有任务入口及公共模块责任。启动、签发前、每 900 秒和收到阶段结果时，分页发现相关 Issues／PR、未答复请求和其他路线适用成果。跨环境以 GitHub 来源任务评论和路线入口交叉引用交接；协议见[跨路线协议](../../docs/cross-route-protocol.md)。公共任务由一个主责路线推进，各路线分别确认采用；公共合并不等于各路线采用，公共记录维护也不增加裁决权。

使用[单一适配器](../../scripts/agent_center.py)选择明确参与者与通道。GitHub 接收方在自己的环境核对原写入者、活动作业、未提交现场、队列及剩余预算，再显式接单；无需可访问远端 App Server。可访问的 Agent Center 活跃任务只向原轮次 `turn/steer`。状态不明先回读，操作结果不明不重发，沉默不表示接受或停工。跨路线请求与后续工程签发分别保留来源；PR 由实际工程签发组创建，开发组以自己的固定身份审查、维护和合并，工程结果回实际签发组，再沿原跨路线请求回传。

当前执行轮次持续监督时，每 900 秒检查一次；用工具在不超过 60 秒的有界等待之间处理新消息和即时升级。最终回复结束监督，不安装后台服务或留下轮询进程。重大变化、预算超支、单动作超过 24 小时、fork／flush 及原合同保留事项立即交用户批准，不等待定时检查。
