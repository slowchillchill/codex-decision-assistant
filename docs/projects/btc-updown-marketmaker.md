# btc-updown-marketmaker 的路线绑定参考

本参考仅在该项目明确选用时加载。它记录协作入口与职责，不保存实时进度或增加执行授权；启动时回读项目当前合同与裁决。

| 参与者 | 责任与现有入口 |
| --- | --- |
| A 决策组 | A 路线合同 [#185](https://github.com/slowchillchill/btc-updown-marketmaker/issues/185)，研究 [#327](https://github.com/slowchillchill/btc-updown-marketmaker/issues/327) |
| B 决策组 | B 路线合同 [#181](https://github.com/slowchillchill/btc-updown-marketmaker/issues/181)；在指定训练服务器执行开发、测试和训练 |
| C 决策组 | C 路线合同 [#215](https://github.com/slowchillchill/btc-updown-marketmaker/issues/215)；只读展示原所属模块的业务事实 |

用户指定由 A 决策组整理[全局合同 #1](https://github.com/slowchillchill/btc-updown-marketmaker/issues/1)及[裁决索引 #62](https://github.com/slowchillchill/btc-updown-marketmaker/issues/62)。B/C 在来源任务提交准确更新请求；A 的整理职责不增加其裁决权限，离线不阻断其他路线不依赖该整理动作的已授权工作。只按既有收录边界维护裁决索引，普通接收回执不产生裁决编号。

[#340](https://github.com/slowchillchill/btc-updown-marketmaker/issues/340)公共统计与 [#342](https://github.com/slowchillchill/btc-updown-marketmaker/issues/342)研究入口说明跨环境协作的实际边界：公共能力交付后，从 GitHub 核对准确版本；消费路线分别判断采用和剩余缺口，无须访问生产者的训练服务器。

公共执行与计算缺口回原模块，策略参数、风险政策和采用结论仍归各路线。[D-0374](https://github.com/slowchillchill/btc-updown-marketmaker/issues/327#issuecomment-6332743060)体现 A 的显式采用不改写 B 的冻结选择；[D-0361](https://github.com/slowchillchill/btc-updown-marketmaker/issues/315#issuecomment-6231818529)要求按实际使用判断留出独立性。成果经 C 展示后若用于设计或选择，也须记录该用途。

实际账号、端点、线程和执行路径只填私有绑定。此参考不触发实例开关机、环境迁移、研究运行或业务仓库改动。
